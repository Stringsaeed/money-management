# Keep authentication optional and email-first

The app remains usable anonymously and local-first; sign-in exists to unlock Household features, not to gate ledger setup. Profile & household is the single Settings entry for session and Household actions: after creating a local Account, onboarding offers an optional sharing prompt, while signing in or signing up returns there to create or join a Household. It lists all memberships and lets the User choose the active Household. New Users create a password explicitly; returning Users enter an email and receive an email link by default, with password sign-in available as a fallback, while a permanently visible password-sign-up action avoids revealing whether an email exists. Better Auth owns credential issuance, verification, reset, and revocation; the app configures the product contract: email links work on iOS, Android, and web through `https://auth.trove.ing`, are single-use for 15 minutes, and a resend invalidates older links. The email-first screen gives generic confirmation to avoid account enumeration. Password recovery uses a distinct reset link rather than treating a recovery link as an authenticated session, then starts a new session after successful reset. Sessions persist until explicit sign-out or server revocation; if remote access ends, the local ledger remains usable while Household/sync features pause behind a sign-in banner. Signing out clears only the remote session, while separately confirmed device-data erasure remains a Danger Zone action. Successful authentication returns to the invoking context when an active Household exists; otherwise it opens Profile & household.
